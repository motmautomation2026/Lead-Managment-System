# UX audit — whole app (UX-1, 2026-11-11)

Baseline: `dev` `656cbad`. Backend 1271 unit tests, frontend 512, first load **298.5 kB gzip** (budget 350).
Method: router (26 routes), shell, `components/crm/*` and every page under `features/*` skimmed; click counts from
the code paths (desktop, mouse, from the page's own URL). Scroll: rough screen heights at 1440×900.

Legend — Pag.: **P** server-paginated (B4 keyset / Load more) · **C** capped by the API (latest N) · **F** fixed /
bounded small list · **U** unpaginated and can grow.

## 3. Top 10 problems

1. Settings Workspace tab is one very long page (Email + WhatsApp + Calendar, each with several forms). **UX-1**
2. Save buttons sit at the bottom of long cards; edits are lost silently when navigating away. **UX-1**
3. No way to find a setting by name; ⌘K only opens "Settings". **UX-1**
4. Growing lists without pagination: team, user accounts, safety events (UX-1); workflows, templates, knowledge
   documents/assets, notifications (UX-4, need backend keyset endpoints).
5. Contact record is 5–7 screens long; key actions scroll away. **UX-3**
6. Repetitive call work has no "next" — back to the list each time. **UX-2**
7. Status is shown as raw text ("qr_ready", "reauth required") without a single next action. **UX-1** (channels), UX-3 (records)
8. Loading states mix "Loading…" text, `LoadingBlock` and skeletons; layout jumps when data arrives. Foundation `SectionSkeleton` (UX-1), rollout UX-2–4.
9. Confirm dialogs don't always say exactly what happens (e.g. Pause sending had no confirm). **UX-1** for Settings.
10. Non-admins see admin sections that only say "Admins only". **UX-1** (hidden, not disabled).
